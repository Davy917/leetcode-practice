### Copilot

你卡住的點其實很典型，而且你已經觀察得很準確了：

`for` 迴圈常常可以「往後模擬幾步」；  
遞迴如果也硬要這樣做，腦力會爆掉。

關鍵建議只有一句：**遞迴不要靠「往後想很多步」，要靠「契約」**。

---

**一個可直接套用的遞迴寫法（4步）**

1. **先定義函式契約**
   - 這個函式輸入是什麼？
   - 回傳值保證什麼？
   - 只寫「這一層的責任」，不管更深層怎麼做。

2. **先寫 base case（停止條件）**
   - 先處理最小問題（例如 `null`、空陣列、`index == n`）。
   - base case 寫對，遞迴就有地板，不會亂飛。

3. **假設子問題已經會做（信任遞迴）**
   - 不要展開 3 層、5 層去腦補。
   - 直接把「下一層回傳的結果」當成已知正確來組合。

4. **把當前層答案組合出來**
   - 通常是：
     - `current + recursive(...)`
     - `left && right`
     - `max(left, right)` 等。

---

**你可以用的口訣（真的有用）**

每次寫遞迴前先默念：

1. 我這個函式「承諾」什麼？
2. 什麼情況立刻回傳？
3. 下一層如果已經正確，我這層怎麼拼答案？

只要這三句講得出來，程式通常就能寫對 80%。

---

**為什麼你在 for 很強、遞迴會卡**

你是偏「模擬型思考」：  
- 迴圈：一步步模擬很適合你。
- 遞迴：需要「抽象層次切換」，不是直覺模擬。

所以不要硬改天性，而是轉成你擅長的形式：

- 先把遞迴畫成「一層決策 + 子問題黑盒」
- 只追 1 層，不追全部層
- 用小測資驗證（2~4 個節點）代替腦內跑完整樹

---

**實戰檢查清單（每次照抄）**

寫完遞迴後檢查：

1. base case 有沒有覆蓋所有最小情況？
2. 遞迴呼叫有沒有「朝 base case 靠近」？（問題規模變小）
3. 同一層有沒有重複做不必要工作？
4. 回傳式是 `&&` 還是 `||` 邏輯正確嗎？
5. 用最小反例測：
   - 空
   - 單一元素
   - 剛好錯一點點

---

**降低複雜度的練習法（每天 15 分鐘）**

1. 先做「線性遞迴」：sum、factorial、反轉字串  
2. 再做「二叉遞迴」：same tree、max depth  
3. 最後做「搜尋 + 比對」：subtree、path sum  

每題都先寫 3 行註解（契約/base case/組合），再寫程式。  
先追求穩定，不追求一次寫很快。
