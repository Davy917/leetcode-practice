注意，你的提交結果其實是 **Time Limit Exceeded（超時）**，不是通過喔。你運行的是小樣本測試用例所以通過了，但 LeetCode 提交時遇到了一個很大的測資就超時了。

失敗的測資是一棵**極度右偏的樹**（每個節點只有右子節點），節點數非常多。

---

### ⏱️ 為什麼會超時？

問題出在這裡：

```javascript
const isBST = valid(root, -Infinity, Infinity)
```

你在 `dfs` 中對**每個節點**都呼叫 `valid`，而 `valid` 本身又會遍歷整棵子樹。這導致時間複雜度是 **O(n²)**，對於 n = 40000 的測資就會超時。

---

### 💡 優化方向

你需要**一次後序遍歷就搞定所有判斷**。

想想看：當你做 `dfs` 時，左右子樹的結果其實已經算出來了。如果你能讓 `dfs` 一次回傳足夠的資訊，就不需要再呼叫 `valid`。

試著讓 `dfs` 回傳一個結構，包含：

```
[isBST, sum, minVal, maxVal]
```

- `isBST`：這棵子樹是否為 BST
- `sum`：這棵子樹的總和
- `minVal`：這棵子樹的最小值
- `maxVal`：這棵子樹的最大值

這樣在每個節點，你可以用 **O(1)** 的時間判斷：
- 左子樹是 BST，且右子樹也是 BST
- 且 `左子樹的 maxVal < 當前節點值 < 右子樹的 minVal`

整個演算法就降為 **O(n)**。
