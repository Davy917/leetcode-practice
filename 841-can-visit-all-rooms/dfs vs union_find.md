# 這道題「鑰匙和房間」在圖論中可以建模為一個 **有向圖（Directed Graph）**。

## 圖的建模方式

- **節點（Vertex）**：每個房間是一個節點，編號 `0` 到 `n-1`。
- **有向邊（Directed Edge）**：如果房間 `i` 中有房間 `j` 的鑰匙，就存在一條從 `i` 指向 `j` 的有向邊。

## 問題本質

這道題的核心是一個 **可達性問題（Reachability）**：

> 從節點 `0` 出發，沿著有向邊遍歷，是否能到達所有節點？

## 為什麼是有向圖？

因為「房間 A 有房間 B 的鑰匙」只代表你能從 A → B，**不代表**能從 B → A。邊的兩個方向並不對稱，所以是有向圖。

## 補充說明

- 這個圖**可能有環（cycle）**，例如房間 0 有鑰匙到 1，房間 1 也有鑰匙回 0。
- 它**不一定是連通的**，所以才會出現 `false` 的情況（如範例 2 中房間 2 無法到達）。
- 解法上通常用 **DFS 或 BFS** 從節點 0 開始遍歷，最後檢查是否所有節點都被訪問過。


## ✅ DFS — 可以解題

DFS 是這道題最自然、最適合的做法。從房間 0 出發，沿著有向邊（鑰匙）遞歸訪問，最後檢查是否所有房間都被到訪過，完全符合題意。

## ❌ 並查集（Union-Find）— 不適合

並查集的核心假設是 **關係是對稱的（雙向的）**，它擅長處理的是**無向圖的連通性**。

但這道題是**有向圖**，考慮以下反例：

```
rooms = [[1], [0], []]
```

- 房間 0 → 有鑰匙到 1
- 房間 1 → 有鑰匙回 0
- 房間 2 → 沒有鑰匙，也沒人能到達

如果用並查集，`union(0, 1)` 和 `union(1, 0)` 會把 0 和 1 合併到同一集合，但並查集**無法表達「誰能到達誰」的方向性**。你可能會嘗試把每個鑰匙關係都做 `union`，但這樣做會**混淆可達性的方向**。

再看另一個例子：

```
rooms = [[1], []]
```

- 房間 0 → 有鑰匙到 1（能到達）
- 房間 1 → 沒有鑰匙

並查集做 `union(0, 1)` 後，會認為 0 和 1 在同一集合，但你無法從中判斷**是 0 能到達 1，還是 1 能到達 0**。它丟失了方向資訊。

## 總結

| 方法 | 適用性 | 原因 |
|------|--------|------|
| DFS / BFS | ✅ 適合 | 天然支持有向圖遍歷，追蹤可達性 |
| 並查集 | ❌ 不適合 | 設計用於無向圖，無法表達邊的方向 |

簡單記憶：**當問題涉及「方向」或「從某個起點能否到達」時，優先考慮 DFS/BFS；當問題是「兩點是否互相連通（無向）」時，才考慮並查集。**

有興趣的話，你可以再想想：如果題目改成「鑰匙是雙向的（A 有 B 的鑰匙，B 也自動有 A 的鑰匙）」，那並查集是不是就可以用了？
