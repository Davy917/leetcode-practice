這四種語言在「如何讓物件擁有內建功能」的底層設計上，存在著根本性的架構差異。
雖然它們最終的目的相同（讓物件可以使用內建方法），但實現的手段可以分為兩大陣營：JavaScript 獨樹一格的原型繼承，以及其他三者使用的類別繼承（或結構組合）。
以下是它們的核心差異對比：
## 1. Java：嚴格的類別繼承（Class-based）
Java 與 JavaScript 的機制完全不同。Java 沒有原型，它是基於類別（Class）的。

* 如何實現：在 Java 中，所有的類別如果沒有指定繼承誰，預設都會強制繼承一個老祖宗類別叫做 java.lang.Object。
* 與 JS 的差異：Java 的物件結構在編譯時就必須定死（不能像您在 JS 中隨時 dude.age = 34 動態加上去）。物件擁有的方法是從類別（Class）結構中層層繼承下來的，而不是透過隱藏的原型鏈指標。

## 2. Python：動態的類別繼承（一切皆物件）
Python 雖然與 Java 一樣是基於類別，但它像 JavaScript 一樣具有高度的「動態性」。

* 如何實現：在 Python 3 中，所有定義的 Class 預設都繼承自內建的 object 基礎類別。當您呼叫一個方法時，Python 會透過 __mro__（方法解析順序）去尋找父類別。
* 與 JS 的差異：Python 的物件內建有一個類似的原型概念，叫做 __class__（指向建立它的類別），並且每個物件都有一個 __dict__ 字典來儲存自訂屬性。它不需要 JS 那種點對點的隱藏原型鏈，而是直接透過「物件 ➡️ 類別 ➡️ 父類別」的架構來尋找方法。

## 3. Go (Golang)：完全沒有繼承（結構體與組合）
Go 語言的設計理念最為極端，它完全沒有 Class，也沒有繼承，更沒有原型。
* 如何實現：Go 使用的是結構體（struct）。當您宣告一個空的 struct{} 時，它就是絕對乾淨、完全空白的，沒有任何隱藏的底盤或內建方法。
* 與 JS 的差異：Go 提倡「組合優於繼承」。如果您希望一個結構體擁有某些功能，您必須顯式地（Explicit）把其他結構體塞進去（內嵌），或是幫它綁定方法。它在底層不會有像 [[Prototype]] 這種自動幫你包裝好、在背後默默相連的隱藏鏈結。

## 4. JS (JavaScript)：原型繼承（Prototypical Inheritance）
在 JavaScript 中，幾乎所有的物件（Object）在建立時，瀏覽器都會自動幫它貼上一個隱藏的標籤，這個標籤就是 [[Prototype]]。
